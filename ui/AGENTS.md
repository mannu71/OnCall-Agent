## What this repo is

AI Investigation Platform frontend. React + Vite SPA with a Langflow-style
visual workflow builder. Engineers compose investigation pipelines by dragging
nodes, watch agents run in real time via SSE, approve/deny tool requests,
and review synthesised root cause and suggestions.

1. **NEVER modify `src/components/ui/`** — these are shadcn/ui
   auto-generated files. To add a new UI primitive:
   `npx shadcn-ui add [component-name]`

2. **NEVER call `fetch()` directly** in components or pages.
   All API calls go through `src/services/` clients.

3. **NEVER use WebSocket** — the backend streams via SSE.
   The SSE hook is `useWorkflowStream.js` — use it.

4. **NEVER modify `LangflowEditor.jsx`** without reading the entire
   file first and showing the full diff. It is the most critical
   frontend file.

5. **Prefer TanStack Query hooks** in `src/hooks/queries/` for GET/polling;
   keep SSE streaming in `useWorkflowStream.js`.

6. **NEVER add new npm packages** without asking first and updating
   `package.json` with a pinned version.

7. **ALWAYS show diff before applying** any change to existing files.

8. **ALWAYS check that the API contract matches** — when changing
   a service call, verify the backend endpoint schema in
   `agent-api/app/api/v1/schemas/` matches.

9. **The backend API base URL** comes from environment variables —
   never hardcode `localhost:8000` in component files.

## SSE streaming — how live updates work

The backend sends Server-Sent Events during workflow execution.
The frontend consumes them via `useWorkflowStream.js`.

```javascript
// src/hooks/useWorkflowStream.js — how to use
import { useWorkflowStream } from '../hooks/useWorkflowStream'

// In a component:
const { events, status, error } = useWorkflowStream(executionId)

// Event types from backend (see agent-api/app/workflow/event_schema.py):
// { type: "node_start",    node: "cloudwatch_agent", ... }
// { type: "node_complete", node: "cloudwatch_agent", cost_usd: 0.002, ... }
// { type: "node_error",    node: "db_agent", error: "...", ... }
// { type: "tool_request",  tool: "query_table", params: {...}, request_id: "..." }
// { type: "tool_result",   request_id: "...", result: {...}, ... }
// { type: "hitl_pause",    payload: { root_cause, suggestions }, ... }
// { type: "complete",      investigation_id: "...", ... }
```

When building new components that need live updates, always use
`useWorkflowStream` — never open a new SSE connection directly.

## LangflowEditor specifics

- Workflow canvas lives in `LangflowEditor.jsx` — a hand-rolled SVG canvas
  (its own node, edge, port and drag handling). ReactFlow is NOT a dependency.
- Node types defined in `editor/constants/nodeDefinitions.js`
- Workflow JSON saved to backend via `agentApiClient.js`
- Format: `{ nodes: [...], edges: [...] }`, built by `buildExportedWorkflow()`
  in `LangflowEditor.jsx`. The backend consumes it in
  `workflow/schema/node_catalog.py` (type/dialect resolution) and
  `services/visual_workflow_executor.py` (execution).

## API contract — backend endpoints consumed

```javascript
// All via src/services/agentApiClient.js and apiClient.js

GET    /api/v1/workflows              → list workflows
POST   /api/v1/workflows              → create workflow
GET    /api/v1/workflows/{id}         → get workflow
PUT    /api/v1/workflows/{id}         → update workflow
DELETE /api/v1/workflows/{id}         → delete workflow
POST   /api/v1/workflows/{id}/execute → trigger execution → returns execution_id
GET    /api/v1/executions/{id}        → execution status
GET    /api/v1/executions/{id}/stream → SSE stream of execution events
POST   /api/v1/executions/{id}/approve → resume after HITL interrupt

GET    /api/v1/llm_config             → available LLM providers
GET    /api/v1/mcp_config             → MCP server configurations
GET    /api/v1/skills                 → available agent skills
GET    /api/v1/trajectories           → past investigation trajectories

GET    /api/v1/releases               → Azure DevOps releases
POST   /api/v1/releases               → trigger release workflow
```
